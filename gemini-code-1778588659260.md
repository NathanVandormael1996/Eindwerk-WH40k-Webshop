# Antigravity Rules & Design System

## 1. Purpose of this Document
This document is the definitive building and writing guideline for the **Antigravity** project in VS Code. Everything generated, modified, or proposed must be compatible with:
- Laravel 13
- Livewire 4
- The official Laravel Livewire starter kit (already installed as a base)
- Flux UI free tier
- MySQL or MariaDB
- Pest (Testing)

This project is not a generic demo app. It is a senior-level CMS and webshop backend built in Laravel 13 + Livewire 4, fully integrating the **Antigravity Design System** (inspired by Kraken). 

## 2. Visual Theme & Atmosphere (Kraken-Inspired)

Antigravity utilizes a clean, high-trust "Crypto-Professional" aesthetic. The interface operates on white surfaces with **Antigravity Purple** as the commanding brand anchor.

### Key Characteristics:
- **Primary Brand:** Antigravity Purple (`#7132f5`) with darker variants (`#5741d8`, `#5b1ecf`).
- **Typography:** Dual font system: `Antigravity-Display` (bold, negative tracking for headings) and `Antigravity-Product` (UI workhorse).
- **Text & Neutrals:** Near-black (`#101114`) primary text, cool blue-gray neutral scale (`#686b82`, `#9497a9`).
- **Shapes:** 12px border-radius standard for buttons and primary containers. No pill-shaped buttons.
- **Depth:** Whisper-level shadows (`rgba(0,0,0,0.03) 0px 4px 24px`).
- **Success States:** Green accent (`#149e61`) for positive actions and badges.

### Component Stylings:
- **Primary Button:** `#7132f5` bg, `#ffffff` text, 12px radius, 13px 16px padding.
- **Outlined Button:** `#ffffff` bg, `#5741d8` text and 1px border, 12px radius.
- **Subtle Button:** `rgba(133,91,251,0.16)` bg, `#7132f5` text, 12px radius.
- **Badges:** Success (`rgba(20,158,97,0.16)` bg, `#026b3f` text, 6px radius), Neutral (`rgba(104,107,130,0.12)` bg, `#484b5e` text, 8px radius).

## 3. Non-Negotiable Version & Syntax Rules

### General
Use only syntax, project structure, and patterns compatible with **Laravel 13** and **Livewire 4**.

### Forbidden:
- Livewire 2 or Livewire 3 syntax if it deviates from Livewire 4.
- Old Volt route syntax like `Volt::route()`.
- Code snippets based on Laravel 10, 11, or 12 if not 100% compatible.
- Replacing the current starter kit with Jetstream.
- Filament as an admin framework (unless explicitly decided later).
- Inertia, Vue, React, or Alpine-first solutions for logic that belongs in Livewire 4.
- Business logic in Blade views, routes, or models (except scopes, accessors, casts).
- Uncontrolled inline queries in views or render methods.
- Using `float` for monetary values.
- Hardcoded IDs.
- Tutorial-style hacks over standard Laravel conventions.

### Mandatory:
- `Route::livewire()` for full-page Livewire components.
- **Livewire 4 single-file components** as the default.
- Constructor dependency injection.
- **Actions** for concrete business operations.
- **Services** for external integrations (e.g., Stripe).
- **Enums** for status fields.
- **Policies** for authorization and custom **Middleware** for admin protection.
- Eager loading to prevent N+1 issues.
- Typed properties, type hints, and return types.

## 4. Livewire 4 Rules

### Component Strategy
- Use **single-file Livewire components** by default.
- Page components should be single-file.
- Keep components thin. Complex logic must be extracted to Actions, Services, Form Objects, or computed properties.

### Component Rules
- One clear responsibility per component.
- No heavy business logic or massive query chains.
- Use `#[Computed]` for derived state.
- Use `#[Validate]` or a dedicated Form Object for validation.
- Use `WithPagination` and `WithFileUploads` where necessary.

### Routing & State
- State for UI goes in Livewire. Domain state goes in the database/services.
- Shopping cart state may live in the session for guests, and database for logged-in users.
- Clear routing: `Route::get()` for classic controllers, `Route::livewire()` for full-page Livewire screens.
